# 表情包库

让 bot 攒群里的表情包，打上标签，按聊天语境挑着发。

出站协议和 QQ 收藏表情是同一个：模型在回复里写 `[表情:名称]`。收藏表情优先，查不到才回落图库。

## 先配看图渠道

**不配这一步，收进来的图永远打不上标签，也就永远进不了检索。**

控制台「表情包」页有一块看图渠道：选渠道、填地址、点「拉取」挑模型、填 key。它写的是 `data/config.yaml` 的 `system_models.image`，`read_image` 工具用的是同一份。

「渠道」决定按谁的格式发请求，四种都支持（OpenAI / Responses / Claude / Gemini 原生）。它也决定地址写到哪一级：OpenAI 系要带 `/v1`，Claude 和 Gemini 不带，多带的版本段会被去掉。

留空的规则是分层的，不是一刀切：

| 填了什么 | 按谁的格式发 |
|---|---|
| 全空 | 整条跟随主渠道，格式也跟着它 |
| 只填了地址 | OpenAI —— 换了地址就不能假定对面还说主渠道那套话，中转站按最小公约数算 |
| 选了渠道 | 就按选的那家 |

所以主渠道是 Gemini 或 Claude 原生时，什么都不填也能打标；而填了一个中转站地址却没选渠道时，发的是 OpenAI 格式。

## 开始收图

控制台「表情包 → 收集设置」，或 `config/qq.yaml`：

```yaml
extensions:
  sticker:
    collect: true
    strategy: loose         # strict 只收 QQ 标了表情包的；loose 再放行看着不像截图的；none 全收
    groups: []              # 只从这些群收，留空表示所有已授权的群
    auto_accept: false      # false 时先进待审池，人工筛过才入库
```

热载，改完两秒生效，不用重启。

三档过滤的差别：

- `strict` —— 只认 QQ 自己标成表情包的（商城表情、收藏表情、带 `sub_type=1` 的图）。零误收，但别人直接发图片文件当表情包的收不到。
- `loose`（默认）—— 在 strict 基础上，普通图片再过一遍尺寸判定：长宽比超过 2.5、大照片、典型手机截图比例的一律不收。**动图永远放行**，表情包绝大多数是 GIF 而截图不会是动的。
- `none` —— 去重之后全收。

判定只读文件头前 64KB 取宽高，不解码整图 —— 它跑在每条群消息的路径上。

## 管理

控制台「表情包」页：缩略图网格、改名、改标签、待审筛选、手动上传、从目录导入、重新打标。

聊天里（写操作限管理员）：

```
/表情包 统计
/表情包 列表 [数量]      /表情包 待审
/表情包 通过 名字        /表情包 丢弃 名字      /表情包 删除 名字
/表情包 改名 旧名 新名   /表情包 标签 名字 开心,猫
/表情包 重打标 [失败]    /表情包 备份
```

**丢弃**会记住这张图的哈希，同一张再出现也不会收；**删除**是彻底清掉记录，之后还能被重新收。

## 图存在哪

```
data/stickers/
  ├ stickers.sqlite3     索引（WAL，几个进程同时读写）
  ├ pending/             待审
  ├ library/             在库
  └ backups/             /表情包 备份 的产物
```

**多开时这个目录是软链**，指向 `/opt/kazebot-data/stickers/`，几个号共用一份。做成软链而不是配绝对路径，是因为附件白名单只认工作区内的 `data/` 前缀，库放在外面就发不出去。

图库**不会被定时清理动到** —— `engine/data_cleanup.py` 只扫显式点名的子目录，`data/stickers` 不在列。`tests/test_sticker_library_survives_cleanup.py` 钉住了这一点，谁往任务表里加一行会被测试挡下。

注意别把库放进 `data/attachments/`，那个目录 24 小时递归清一次，不看扩展名。

## 发图那一侧

按当前这句话粗排出 Top-N 候选（默认 12 张），带着标签注入提示词，模型自己决定发不发、发哪张。

- 语境不明确时（既没有意图词也没有标签命中）分数会被压到阈值以下，宁可不发也不在闲聊里乱发图。
- 同一会话 `repeat_window_sec`（默认半小时）内发过的图不再出现在候选里。
- 发图走 base64 而不是本地路径：库是几个号共用的，NapCat 容器里没有那个挂载。

## 接梗（默认关）

```yaml
extensions:
  sticker:
    combat: false
    burst_probability: 0.0
```

群里连着刷图时跟一张。要求连图来自**至少两个人**（一个人连发是自娱自乐），中间夹了纯文本就断。语境取群历史里最近的文本，取不到就不发 —— 为了接一张图再调一次多模态不划算。

`burst_probability` 是自己发完之后再补一张的概率，0 表示不补。

## 排障

| 现象 | 看哪 |
|---|---|
| 收不到图 | `collect` 开了吗；`groups` 白名单；`strategy` 是不是 strict 而对方发的是普通图片 |
| 图收进来但一直没标签 | 看图渠道没配好，日志搜「打标停用」 |
| 有标签但模型不发 | `/表情包 统计` 看 usable 数；语境可能被判成闲聊；或者半小时内刚发过 |
| 打不开库 | systemd 的 `ReadWritePaths` 要放开共享目录 —— 它按真实路径判权限，软链不算 |

进度和错误都在 bot 日志里，前缀是 `stickers`。
